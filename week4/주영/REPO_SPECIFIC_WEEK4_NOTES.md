# Week 4 — VLN Next-Action Prediction (Qwen3-VL-2B LoRA) — integration notes

This `week4/` package is the "brain" the Week 3 simulator code
(`IAmGoodNavigator/go2_physics_teleop.py`, `demo.py`) calls into when
`--go2-physics-week4-vln-checkpoint` is set. Additive: with the flag absent,
every Week 1-3 path runs unchanged. All values below follow the official
assignment spec ("Deep Learning Term Project Week 4").

## Task (per spec)

VLN next-action prediction. Inputs: full navigation instruction + egocentric RGB
frames `[I_{t-1}, I_t]`. Output: EXACTLY one of four action strings, generated by
a LoRA-fine-tuned `Qwen/Qwen3-VL-2B-Instruct`. Closed-loop in IsaacSim.

## Action set (exactly four — "degree" singular)

```
Move forward 25cm     -> [1.0, 0.0,  0.000] m/s,rad/s  for 0.25 s   (1.0*0.25 = 0.25 m)
Turn left 15 degree   -> [0.0, 0.0,  1.047]            for 0.25 s   (1.047*0.25 ~= 15 deg)
Turn right 15 degree  -> [0.0, 0.0, -1.047]            for 0.25 s
Stop                  -> [0.0, 0.0,  0.000]            terminate episode
```
parquet `observation.action` id -> string: 0=Stop, 1=Move forward 25cm,
2=Turn left 15 degree, 3=Turn right 15 degree. Invalid model output -> fallback
`Move forward 25cm` (counted in invalid-output rate).

## Commander contract (consumed by the sim loop, identical to Week 2/3)

`quit_requested`, `mission_complete` (attrs); `reset()`; `advance() -> np.float32[3]`
(one call per control step); `status_text()`. VLM inference runs once per decision;
between decisions the held velocity replays for `ceil(0.25/control_dt)` steps.
Image rule: `[I_{t-1}, I_t]`; at t=0 the first frame is duplicated → `[I_0, I_0]`.

## Dataset (VLN-VERSE, real format — verified)

* Repo `Eyz/VLNVerse_data` (public). Use `raw_data/final_splits/fine_train.json.gz`
  → `{"episodes": [{scan, episode_id, instruction, ...}]}`. Episode folder name =
  `episode_id` minus `"<scan>_"` prefix (e.g. `kujiale_0254_23_4` → `23_4`).
* Per-episode: `data/chunk-000/episode_000000.parquet` (column `observation.action`),
  `meta/episodes.jsonl` (`instruction_text`), and **RGB as `videos/chunk-000/
  observation.images.rgb/rgb.npy`** — shape `[T,256,256,3]` uint8 (NOT mp4).
  `depth.npy` is unused and skipped on download.
* Footprint: ~7 MB rgb/episode → fine_train (3963 eps) ≈ ~28 GB rgb-only. Eval
  scenes (top53, `Eyz/VLNVerse_scene`) ≈ 52.9 GB.

## CUDA / environment

* Env `goodnav` (python 3.10) under the existing Anaconda. The Anaconda launcher is
  broken by the space in `C:\Users\user one\...`; invoke the interpreter directly:
  `& "C:\Users\user one\anaconda3\envs\goodnav\python.exe" ...` (always `-m`, never the .exe shims).
* PyTorch cu128 (Blackwell). The Week 3 README's cu118 does NOT support sm_120.
* HuggingFace cache symlinks fail on Windows without admin/Developer Mode → set
  `HF_HUB_DISABLE_SYMLINKS=1` (copy mode). Console is cp949 → keep prints ASCII-only.

## Isaac Sim / Blackwell risk (closed-loop eval only)

Isaac Sim 4.5 does NOT officially support RTX 50-series (sm_120); the documented
50-series workaround is to replace its bundled torch 2.5.1 with a cu128 build
(already satisfied here). The RTX renderer itself may still fail on 4.5/Blackwell;
Isaac Sim 5.x has better Blackwell support but its own 5070 Ti crash reports
(driver-sensitive). Installed into a separate `isaaclab` env to avoid disturbing
`goodnav`. Egocentric capture (`Week4EgocentricCapture`, omni.replicator RGB
annotator) degrades to black frames on failure — validate with a frame-capture
test before trusting closed-loop numbers.
